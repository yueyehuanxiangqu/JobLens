# v0.6.1 本地测试版

## 本次变化

- “Jobs on this page” 移到 Library 与 Inserted jobs 上方。
- 每个岗位卡片增加 “Analyze this job” / “Re-analyze this job”。按钮只分析该岗位；后台先切换岗位并校验读取到的岗位 ID。详情没有加载完成时会报错，不分析其他岗位。
- Debug 显示失败阶段、请求地址、请求与返回模型、HTTP 状态、结束原因、输入/输出字符数、输出限制、超时、提示词版本及结构错误，并给出下一步建议。
- “Copy diagnostics” 复制诊断报告，可用于反馈问题；不包含 API Key、简历正文、JD 正文或模型原始回复。
- 分析完成时侧边栏会消费单岗位/插入岗位响应中的结果；列表分析会在响应返回后刷新缓存，并对重复广播去重。即使结果广播发生时序异常，也不会一直停留在“Analyzing”。
- 旧历史的诊断信息保持原样；需要重新分析才能产生新增字段。供应商隔离、模型下拉和自定义设置沿用 v0.6.0。

## 保留数据更新

1. 记下原扩展的 ID 和加载来源目录，不卸载原扩展。
2. 暂停分析，关闭侧栏，备份原加载目录。
3. 解压 `linkedin-job-match-v0.6.1.zip`，把包含 `manifest.json` 的那层内容覆盖到原目录，路径保持不变。
4. 在 `chrome://extensions/` 点击原扩展的重新加载，确认版本 0.6.1，然后刷新 LinkedIn / Indeed 页面。

本包的 `manifest.json` 位于 ZIP 根目录，与 v0.5.0 的打包结构一致。首次安装也可以解压后加载该目录；已有用户若拖拽 ZIP 创建了另一扩展，它的数据与原扩展独立。

## 测试要点

1. 检查顺序：Jobs on this page → Library → Inserted jobs。
2. 在网站选中 A 岗位时，点击列表中 B 的单独分析按钮，确认得到 B 的结果。
3. 已分析岗位可以重新分析，按钮不会启动整个列表分析。
4. 使用错误模型 ID 测试失败，展开 Debug 并复制报告；核对供应商、模型和失败阶段。
5. 检查旧简历、历史、收藏、自定义颜色和供应商设置仍然可用。
6. 用 OpenRouter 测试一个已通过连接测试的模型，确认分析完成后结果会显示；若仍异常，复制该结果的 Debug diagnostics。

此版本仅本地构建，未发布。自动化采用模拟接口；浏览器与真实模型由用户测试。
