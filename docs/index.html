v0.6.4 · Evidence contract

Four modes. One evidence contract.

One evidence-verification foundation supports four modes: Strict stays close to direct comparable evidence, Balanced recognizes documented partial and transferable evidence, Potential surfaces projects and adjacent experience, and Sponsorship-first uses balanced capability anchors while keeping sponsorship risk separate. Sponsorship-first never adds a Sponsorship Fit percentage to the capability score. All four modes share the same matrix; the extension validates quotations and calculates the score.

Partial Documented evidence covers only part of the requirement.
Transferable Adjacent experience is relevant, but not a direct match.
Unknown vs. unmet Silence means not documented; explicit contradiction is a different result.
Not assessed A dimension with no extracted JD requirement does not create a fake scored item.

Build the extension locally ↗

Ready when you are

A small build. A useful surface.

Run it from source, load the built extension in Chrome, and keep your provider settings in the side panel.

Build the extension 
npm install
npm run build

Build

Install dependencies and create the production-ready dist/ folder.

Load

Open chrome://extensions/, enable Developer mode, and choose Load unpacked.

Choose

Select dist/. The repository source root is not the built extension package.

Update in place

For v0.6.4 testing, run npm run build from main, then replace the contents of the existing Chrome extension Location with the generated dist/ files, click Reload, and refresh LinkedIn or Indeed. You can also use the v0.6.4 ZIP. Loading a new folder creates separate storage; the legacy persistentResume record migrates into the resume library on first read.
